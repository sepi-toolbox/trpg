# SEPI TRPG

[![CI](https://github.com/sepi-toolbox/trpg/actions/workflows/ci.yml/badge.svg)](https://github.com/sepi-toolbox/trpg/actions/workflows/ci.yml)
[![Deploy](https://github.com/sepi-toolbox/trpg/actions/workflows/deploy.yml/badge.svg)](https://github.com/sepi-toolbox/trpg/actions/workflows/deploy.yml)

테이블탑 RPG 규칙을 그대로 구현한 브라우저 던전 크롤러.

**플레이: https://sepi-toolbox.github.io/trpg/**

d20 판정 · 선제 순서 · 유리함/불리함 · 크리티컬 같은 TRPG 규칙을 **순수 함수로 구현한 규칙 엔진**과,
클래스 · 몬스터 · 기술 · 층 구성을 전부 담은 **JSON 데이터 테이블**, 그리고 그걸 굴려 보는 웹 UI로 이루어져 있습니다.

```bash
npm install
npm run dev       # 개발 서버
npm test          # 규칙 엔진 + 밸런스 가드레일 테스트
npm run balance   # 밸런스 시뮬레이션 리포트
npm run build     # 프로덕션 빌드 (dist/)
```

## 구조

```
src/
  rules/          규칙 엔진 — UI도 데이터도 모르는 순수 TS
    rng.ts        시드 기반 결정론적 난수 (같은 시드 = 같은 결과)
    dice.ts       "2d6+3" 표기법 파서 / 굴림 / 기대값 계산
    check.ts      능력치 보정, 숙련 보너스, d20 판정, 공격 횟수
    character.ts  캐릭터 생성, 방어도/명중 산출, 경험치·레벨
    combat.ts     선제 순서, 명중·데미지 해결, 기술, 버프, 적 AI
  data/           데이터 테이블 (JSON) + 무결성 검증
    classes.json  weapons.json  armor.json  skills.json
    monsters.json dungeon.json
  game/
    engine.ts     탐험 진행 — 방 추첨, 함정/보물/제단, 전투 정산
    autoplay.ts   "합리적인 플레이어" 정책 (밸런스 측정용)
  ui/             React 컴포넌트
scripts/
  balance.ts      밸런스 시뮬레이터 CLI
```

핵심 원칙 두 가지:

1. **규칙은 데이터에 있다.** 기술의 크리티컬 범위, 명중 방식, 버프 수치는 코드가 아니라 `skills.json`에 있습니다. 밸런스 조정은 JSON만 고치면 됩니다.
2. **모든 무작위는 시드에서 나온다.** `Math.random()`을 어디서도 쓰지 않습니다. 같은 시드는 같은 전투 로그를 재현하므로 규칙 검증과 밸런스 비교가 가능합니다.

## 규칙 요약

| 항목 | 규칙 |
|---|---|
| 능력치 | 근력·민첩·체력·지능·의지·매력 / 보정 = `내림((점수 - 10) / 2)` |
| 능력치 생성 | 4d6 중 최저 1개 제외, 또는 표준 배열 `15/14/13/12/10/8` — **클래스 우선순위대로 자동 배분** |
| 판정 | `d20 + 능력치 보정 + 숙련 보너스` ≥ 난이도(DC) |
| 자연 20 / 자연 1 | 보정과 무관하게 무조건 성공 / 무조건 실패 |
| 유리함·불리함 | d20을 2개 굴려 높은 눈 / 낮은 눈 채택 |
| 숙련 보너스 | `2 + 내림((레벨-1) / 4)` → 1~4렙 +2, 5~8렙 +3 |
| 방어도 | `갑옷 기본값 + min(민첩 보정, 갑옷 상한) + 버프` |
| 명중 | `d20 + 능력치 보정 + 숙련` vs 대상 방어도 |
| 데미지 | `무기 주사위 + 무기 보정 + 능력치 보정` |
| 크리티컬 | 무기별 최소 눈(단검 19+) 이상이면 **데미지 주사위만 2배** (보정은 1회) |
| 선제 | `d20 + 민첩 보정` 내림차순, 동점이면 플레이어 우선 |
| 추가 공격 | 5레벨 2회, 10레벨 3회 — 대상이 죽으면 남은 공격은 다음 적에게 |
| 1레벨 생명력 | `생명력 주사위 최대치 + 체력 보정 + 4` |
| 레벨업 | 완전 회복 + 기술 사용 횟수 초기화 |
| 짧은 휴식 | 전투 승리 시 최대 생명력 30% + 기술 1회씩 회복 |

던전은 5개 층, 층당 5개 방(보스 층은 1개). 각 방은 가중치 표에서 전투·보물·함정·야영지·제단 중 하나를 뽑고,
층의 마지막 방은 반드시 전투입니다.

## 밸런스

`npm run balance` 는 `src/game/autoplay.ts` 의 "합리적인 플레이어" 정책으로 클래스당 300판을 자동 주파합니다.
최적 플레이가 아니라 평균적인 판단(위험하면 회복 → 어려운 싸움에 버프 → 기술 공격 → 평타)을 흉내 낸 것이라,
여기서 나오는 클리어율이 사실상 이 게임의 체감 난이도입니다.

현재 수치 (시드 0..299):

| 클래스 | 클리어율 | 평균 도달 층 |
|---|---|---|
| 전사 | 15.0% | 3.79 |
| 성직자 | 8.0% | 3.49 |
| 도적 | 7.0% | 3.08 |
| 마법사 | 2.0% | 3.49 |

마법사가 가장 어렵습니다 — 화력은 가장 높지만 자원이 떨어지면 버티지 못합니다. 의도된 난이도 차이지만,
전사와의 격차(7배)는 더 좁힐 여지가 있습니다.

**테스트가 밸런스를 지킵니다.** `src/game/engine.test.ts` 의 가드레일이 다음을 강제합니다.

- 모든 클래스가 200시드 안에 최소 1회 클리어 (= 플레이 불가능한 클래스가 없다)
- 어떤 클래스도 클리어율 50% 미만 (= 난이도가 살아 있다)
- 평균 도달 층 2층 초과, 1층 사망률 40% 미만

JSON 테이블을 고쳐서 이 조건이 깨지면 CI가 빨간불이 됩니다. 조정 루프는 이렇습니다.

```bash
# 1. 데이터 테이블 수정 (예: src/data/monsters.json)
# 2. 분포 확인
npm run balance -- 1000
# 3. 가드레일 통과 확인
npm test
```

`src/data/index.ts` 의 `validateData()` 는 참조 깨짐(없는 무기 id 등)과 잘못된 주사위 표기를 잡아냅니다.
웹 UI 하단 "규칙 · 데이터 테이블 보기"에서 기대 데미지까지 함께 볼 수 있습니다.

## 알려진 미완성

- 금화는 획득만 하고 쓸 곳이 없습니다 (점수 역할). 상점/소모품이 다음 후보입니다.
- 파티는 1인 고정입니다. `Combatant.side` 는 파티 확장을 염두에 두고 남겨 뒀습니다.
- 적 AI는 항상 영웅을 공격합니다. 대상 선택 로직이 들어갈 자리는 `runFoeTurns` 입니다.
- 무기/방어구 교체 UI가 없습니다. 데이터에는 대도끼·판금 갑옷이 이미 있습니다.

## 배포

`main` 에 푸시하면 GitHub Actions가 테스트 → 빌드 → GitHub Pages 배포를 수행합니다.
저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 설정해야 첫 배포가 동작합니다.
