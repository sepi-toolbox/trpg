# 황야의 파수탑 — DB 시스템

[![CI](https://github.com/sepi-toolbox/trpg/actions/workflows/ci.yml/badge.svg)](https://github.com/sepi-toolbox/trpg/actions/workflows/ci.yml)
[![Deploy](https://github.com/sepi-toolbox/trpg/actions/workflows/deploy.yml/badge.svg)](https://github.com/sepi-toolbox/trpg/actions/workflows/deploy.yml)

테이블탑 RPG 규칙을 그대로 구현한 규칙 엔진과, 그 위에서 도는 1인 모험 웹게임.

**플레이: https://sepi-toolbox.github.io/trpg/**

```bash
npm install
npm run dev       # 개발 서버
npm test          # 엔진 테스트 180개 + 데이터 무결성 + 자동 플레이 가드레일
npm run balance   # 밸런스 시뮬레이션 (자동 플레이 통계)
npm run build     # 프로덕션 빌드
```

## 구조

```
data/              규칙 데이터 (JSON) — 여기만 고치면 밸런스·콘텐츠가 바뀐다
  config.json      옵션 룰 토글 11종
  derived.json     파생 규칙 표 (기본치·피해 보너스·나이·이동력·상태이상)
  kin/skills/abilities/professions/weapons/armor/items/spells/monsters/npcs.json
  tables/          굴림표 — 공포(D8)·전투 사고(D6×2)·중상(D20)·마법 사고(D20)·
                   여정 사고(D12)·사냥감(D6)
src/system/        규칙 엔진 — UI를 모르는 순수 함수
  roll.ts          D20 하향 판정, 용(1)/마(20), 보온/베인, 대결, 푸쉬
  character.ts     생성 파이프라인(검증), 파생치, 소지 한도, 성장
  combat.ts        선제 카드, 명중→리액션→피해, 특수 공격, 죽음 판정
  hazards.ts       상태이상, 휴식 3종, 공포, 독, 질병, 환경 위험, 중상
  magic.ts         시전, 위력·WP, 금속 제한, 그리무아, 습득
  effects.ts       효과 훅(Effect DSL) 해석기 + 능력 발동·습득
  monster.ts       흉포도, 자동 명중 공격표, 저항/면역
  journey.ts       길찾기, 야영, 사냥·낚시·채집·조리
  gear.ts          수리, 명품, 광원, 물체 파괴
  validate.ts      데이터 무결성 검사 (npm test 에 포함)
src/app/           게임 — 세션 오케스트레이션(session.ts) + React UI
  autopilot.ts     "평균적인 플레이어" 자동 플레이 (테스트·밸런스 공유)
docs/
  PLAN.md          구현 플랜 + 해석 결정 기록 (이어서 작업할 때 여기부터)
  SCHEMA.md        데이터 편집 가이드 (🔧 규칙 필드 / ✏️ 콘텐츠 필드)
```

핵심 원칙:

1. **규칙 수치는 데이터에 있다.** 몬스터 공격표, 주문 위력, 옵션 룰 토글까지 전부
   `data/*.json`. 코드는 해석만 한다. 편집 후 `npm test` 가 참조 깨짐·표기 오류·
   표 구멍을 잡아준다 — `docs/SCHEMA.md` 참고.
2. **모든 무작위는 시드에서 나온다.** 같은 시드는 같은 모험을 재현한다.
   규칙 검증·밸런스 비교의 전제 조건.
3. **원문 텍스트는 없다.** 수치·계산식·절차만 구현하고 이름·묘사는 전부 자체 작명.
   `(임시)` 표시가 붙은 텍스트는 교체 대상.

## 규칙 골격

| 항목 | 규칙 |
|---|---|
| 판정 | D20 **하향** — 스킬 레벨 이하면 성공 |
| 용(1) / 마(20) | 무조건 성공(크리티컬) / 무조건 실패(사고표, 푸쉬 불가) |
| 보온/베인 | D20 추가 굴림 후 낮은/높은 눈 채택. 1:1 상쇄 |
| 능력치 | 6종(3~18) → 구간표로 기본치 3~7. 훈련 스킬 = 기본치 ×2 |
| 파생치 | HP=체력, WP=의지, 이동력=종족+민첩 보정, 피해 보너스=근력/민첩 구간 |
| 선제 | 카드 1~10 무작위. 리액션(패리·회피)은 자기 턴 소모 |
| 크리티컬 | 주사위 2배 / 추가 공격 / 방어구 무시(관통) 중 선택. 용으로만 방어 가능 |
| 0 HP | 죽음 판정(체력) — 3성공 D6 회복 / 3실패 사망. 용=2성공, 마=2실패 |
| 상태이상 | 6종, 능력치 1:1 — 해당 능력치 판정에 베인. 푸쉬의 대가 |
| 휴식 | 라운드(D6 WP) / 스트레치(D6 HP+D6 WP+상태 1) / 시프트(전량) — 시프트당 1회 |
| 마법 | 유파 스킬 판정. 위력 1~3 = WP 2/4/6. 트릭은 자동 성공 1 WP. **금속 장비 시 시전 불가** |
| 몬스터 | 명중 굴림 없이 자동 명중하는 D6 공격표(같은 눈 연속 불가). 흉포도 = 라운드당 행동 수 |
| 성장 | 용/마를 굴린 스킬에 마크 → 모험 종료 시 D20 > 현재 레벨이면 +1 |

옵션 룰(푸쉬·피해 유형·중상·특수 공격 등 11종)은 `data/config.json` 토글.

## 밸런스

`npm run balance` 는 자동 플레이 정책으로 모험 전체(생성→여정→조우→보스)를 직업당
N판 주파한다. 현재 수치 (시드 0..99):

| 직업 | 클리어율 | 비고 |
|---|---|---|
| 무인 | 30% | 사망 대부분이 보스전 |
| 술사 | 16% | WP 관리가 생명. 잠입 개전이 한 턴을 벌어 준다 |

훅 승격이 진행되며 규칙이 실제로 물기 시작해(중상·흡혈·짐승 조우·저주 등)
클리어율이 단계적으로 조정돼 왔다. 하향돼 있던 수호자 수치는 데이터에서
다시 조정할 여지가 있다.

수호자(보스)는 1인 기준으로 임시 하향된 상태다 (원문 스케일은 3~5인 파티 전제).
`src/app/session.test.ts` 의 가드레일이 "클리어 가능 + 90% 미만 + 진행 불가 0건"을
강제한다 — 데이터를 고쳐서 이게 깨지면 CI가 빨간불이 된다.

## 남은 작업 (플랜 참조)

규칙서 데이터는 전량 입력 완료 (직업 10·능력 51·주문 66·무기 35·아이템 96·몬스터 13·NPC 20·동물 11).
새 데이터의 이름·묘사는 공란(`name: ""`)이며 화면에는 id 가 임시 표시된다 — 작명은 데이터에서.
UI 미노출 규칙도 전부 화면에 연결됐다: 거리·사거리, 기습/잠입(암습), 대기(카드 교환),
무장 해제·붙잡기·약점 찌르기, 무기 바꿔 들기, 과적, 준비 주문 관리·그리무아 시전.
manual 효과 훅 승격도 1~4군 전부 완료 (222건 → 123건, 잔여는 판단·파티 전제 등 승격
부적합 층 — `docs/MANUAL_HOOKS.md`). 남은 것: 밸런스 조정(데이터), 작명.
`docs/PLAN.md` 의 해석 결정 기록에 규칙 해석 이력이 전부 남아 있다.
